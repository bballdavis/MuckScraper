Access and roles

Groups come from a string array claim in the signed ID token. The provider must also send a verified email.

Comma separated. Blank lets any verified identity from this provider in.
With admin or scraper groups set, roles follow the provider at every sign-in (highest wins, anyone else gets the default role below). Both blank: roles stay as set in Users.
On an identity's first sign-in, link it to the one active account whose email or username equals this claim (ignoring case), instead of refusing it or making a new account. The link is stored, so later changes to the claim don't move it. Only use a claim people can't change for themselves at the provider.
Readers can read everything; Scrapers can also fetch articles and run summaries and analysis. Applies to accounts made on first sign-in and to anyone outside the admin and scraper groups, and is preselected in Users › Add a user. Admin is never a default.
